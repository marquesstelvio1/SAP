# Alert Routing

## Purpose

Alert routing defines how SAPTM sends actionable production alerts to incident tooling without
committing receiver URLs or credentials.

## Production Contract

Alertmanager loads `/etc/alertmanager/alertmanager.yml` from the Kubernetes Secret
`saptm-alertmanager-config` in the `saptm-observability` namespace.

The Secret is generated by External Secrets Operator from the remote property
`INCIDENT_WEBHOOK_URL` using `deploy/kubernetes/external-secrets/alertmanager-config.external-secret.example.yaml`.

## Required Flow

1. Store `INCIDENT_WEBHOOK_URL` in the approved secret manager path for the target environment.
2. Apply the ExternalSecret for `saptm-alertmanager-config`.
3. Verify the generated Secret contains `alertmanager.yml`.
4. Deploy the observability stack.
5. Confirm Alertmanager readiness and a test alert route before production go/no-go.

## Production Rules

- Do not commit real receiver URLs.
- Do not route production alerts to placeholder endpoints.
- Do not deploy observability if `saptm-alertmanager-config` is missing.
- Do not accept a production release without alert route evidence.
- Do not accept production go-live without a named escalation owner and incident rota.
- Rotate incident webhook URLs through the secret manager, not through repository changes.

## Acceptance Criteria

- Alertmanager deployment mounts configuration from `saptm-alertmanager-config`.
- Observability deploy workflow verifies `alertmanager.yml` before applying the stack.
- ExternalSecret template renders `alertmanager.yml` from `INCIDENT_WEBHOOK_URL`.
- Release evidence requires target-cluster alert route verification.
- Release evidence records the escalation owner for production alerts.
